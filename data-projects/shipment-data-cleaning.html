Shipment Data Cleaning — BigQuery SQL

Google BigQuery SQL

End-to-end data cleaning pipeline for a shipment tracking dataset containing whitespace inconsistencies, mixed text casing, placeholder null strings, exact duplicate rows, invalid numeric values, and inconsistent date formats.

Key Results

Rather than a business-metrics dashboard, this project is a data-quality pipeline — so the results here are about the issues found and resolved, not revenue figures:

  • Six distinct data quality issues identified and resolved in a single query: whitespace, inconsistent casing, placeholder null strings, exact duplicates, invalid numeric values, and date logic errors.
  • Exact duplicate rows removed using a windowed ROW_NUMBER() approach, rather than a blunt DISTINCT, so duplication is judged on the full business-meaningful combination of fields rather than row-level noise.
  • Invalid shipment records surfaced, not silently dropped — negative weights are corrected rather than deleted, and shipments where delivery precedes shipping are explicitly flagged as Invalid instead of being hidden from downstream analysis.

The Problem

The raw shipment tracking dataset had the kind of quality issues that quietly break downstream reporting: warehouse and carrier names logged with inconsistent capitalization and stray whitespace, a literal text string "NULL" standing in for true nulls in the damage-reported field, exact duplicate shipment rows inflating counts, weight values that were negative or zero, and ship/delivery dates recorded across multiple formats — some of which weren't valid dates at all. Any aggregation or trend analysis run directly against this data would have produced misleading results without this cleaning step first.

What I Built

A single GoogleSQL query that standardizes, deduplicates, and validates the dataset in one pass:

  • Standardizes text fields — trims whitespace and normalizes casing (INITCAP for city/carrier names, UPPER for state codes) across origin_warehouse, destination_city, destination_state, and carrier.
  • Resolves nulls — converts literal "NULL" strings into true NULL values for damage_reported, and applies COALESCE to give destination_city and delivery_date readable defaults where missing.
  • Removes exact duplicates — uses ROW_NUMBER() in a CTE, partitioned on the combination of warehouse, destination, carrier, ship date, weight, and freight cost, keeping the first shipment_id per group.
  • Fixes invalid numeric values — corrects negative weight_kg entries via ABS() and nulls out zero-weight rows that can't represent a real shipment.
  • Validates date logic — parses ship_date/delivery_date with SAFE.PARSE_DATE (so malformed strings return NULL instead of erroring the query), computes transit days via DATE_DIFF, and flags shipments where delivery precedes shipping as Invalid.

Step-by-Step Walkthrough

Rather than jumping straight to the final combined query, here's how the pipeline was built up one issue at a time — each step isolated and verified before folding it into the next:

1. Removing whitespace

View query 
SELECT shipment_id, 
TRIM(origin_warehouse) AS origin_warehouse,
TRIM(destination_city) AS destination_city,
TRIM(destination_state) AS destination_state,
TRIM(carrier) AS carrier
FROM `data-analyst-project-1-504112.dirty_shipments.dirty-shipments`;

2. Standardizing text casing

View query 
SELECT shipment_id, 
INITCAP(TRIM(origin_warehouse)) AS origin_warehouse,
INITCAP(TRIM(destination_city)) AS destination_city,
UPPER(TRIM(destination_state)) AS destination_state,
INITCAP(TRIM(carrier)) AS carrier
FROM `data-analyst-project-1-504112.dirty_shipments.dirty-shipments`;

3. Replacing the string "NULL" and handling true null values

View query 
SELECT shipment_id, 
CASE 
WHEN damage_reported = 'NULL' THEN NULL
ELSE INITCAP(TRIM(damage_reported))
END AS damage_reported,

COALESCE(destination_city, 'Unknown') AS destination_city, 
COALESCE(delivery_date, 'Not Yet Delivered') AS delivery_date,

INITCAP(TRIM(origin_warehouse)) AS origin_warehouse,
INITCAP(TRIM(destination_city)) AS destination_city,
UPPER(TRIM(destination_state)) AS destination_state,
INITCAP(TRIM(carrier)) AS carrier
FROM `data-analyst-project-1-504112.dirty_shipments.dirty-shipments`;

4. Removing exact duplicate rows

View query 
WITH ranked AS (
SELECT *, ROW_NUMBER() OVER ( 
PARTITION BY origin_warehouse, destination_city, carrier, ship_date, CAST(weight_kg AS STRING), CAST(freight_cost AS STRING)
ORDER BY shipment_id
) AS row_number
FROM `data-analyst-project-1-504112.dirty_shipments.dirty-shipments`
)
SELECT * EXCEPT (row_number)
FROM ranked
WHERE row_number = 1;

5. Fixing negative and suspicious numeric values

View query 
SELECT shipment_id,
CASE 
WHEN weight_kg < 0 THEN ABS(weight_kg)
WHEN weight_kg = 0 THEN NULL 
ELSE weight_kg
END AS weight_kg_cleaned
FROM `data-analyst-project-1-504112.dirty_shipments.dirty-shipments`;

6. Validating date logic (delivery after ship date)

View query 
SELECT shipment_id, ship_date, delivery_date,
DATE_DIFF(
SAFE.PARSE_DATE("%Y-%m-%d", delivery_date),
SAFE.PARSE_DATE("%Y-%m-%d", ship_date),
DAY
) AS transit_days,
CASE 
WHEN SAFE.PARSE_DATE("%Y-%m-%d", delivery_date) < SAFE.PARSE_DATE("%Y-%m-%d", ship_date) THEN 'Invalid'
WHEN SAFE.PARSE_DATE("%Y-%m-%d", delivery_date) = SAFE.PARSE_DATE("%Y-%m-%d", ship_date) THEN 'Same Day Delivery'
ELSE 'Valid'
END AS data_quality_flag
FROM `data-analyst-project-1-504112.dirty_shipments.dirty-shipments`;

Known Limitation

delivery_date contains multiple date formats in the source data (YYYY-MM-DD, MM/DD/YYYY, YYYY/MM/DD, Month DD YYYY, plus a non-date placeholder for undelivered shipments). SAFE.PARSE_DATE is currently set to one format pattern, so rows in other formats parse to NULL and their transit_days/data_quality_flag can't be reliably computed — those rows currently fall through to a default Valid flag rather than being caught explicitly. Next step: add format detection (or a COALESCE across multiple SAFE.PARSE_DATE patterns) and an explicit Unparseable flag branch.

Query

-- Removing whitespace, standardizing casing, handling nulls, deduping, cleaning numerics, validating dates
WITH ranked AS (
  SELECT *, 
    ROW_NUMBER() OVER ( 
      PARTITION BY origin_warehouse, destination_city, carrier, ship_date, 
                   CAST(weight_kg AS STRING), CAST(freight_cost AS STRING)
      ORDER BY shipment_id
    ) AS row_number
  FROM `data-analyst-project-1-504112.dirty_shipments.dirty-shipments`
)
SELECT 
  shipment_id,
  CASE 
    WHEN damage_reported = 'NULL' THEN NULL
    ELSE INITCAP(TRIM(damage_reported))
  END AS damage_reported,
  COALESCE(INITCAP(TRIM(destination_city)), 'Unknown') AS destination_city,
  COALESCE(delivery_date, 'Not Yet Delivered') AS delivery_date,
  INITCAP(TRIM(origin_warehouse)) AS origin_warehouse,
  UPPER(TRIM(destination_state)) AS destination_state,
  INITCAP(TRIM(carrier)) AS carrier,
  ship_date,
  CASE 
    WHEN weight_kg < 0 THEN ABS(weight_kg)
    WHEN weight_kg = 0 THEN NULL 
    ELSE weight_kg
  END AS weight_kg_cleaned,
  DATE_DIFF(
    SAFE.PARSE_DATE("%Y-%m-%d", delivery_date),
    SAFE.PARSE_DATE("%Y-%m-%d", ship_date),
    DAY
  ) AS transit_days,
  CASE 
    WHEN SAFE.PARSE_DATE("%Y-%m-%d", delivery_date) < SAFE.PARSE_DATE("%Y-%m-%d", ship_date) THEN 'Invalid'
    WHEN SAFE.PARSE_DATE("%Y-%m-%d", delivery_date) = SAFE.PARSE_DATE("%Y-%m-%d", ship_date) THEN 'Same Day Delivery'
    ELSE 'Valid'
  END AS data_quality_flag
FROM ranked
WHERE row_number = 1;
